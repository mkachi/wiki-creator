# 위키 작성 기준

이 문서는 근거·상태·문서 형식의 단일 기준이다. 작업 순서는 [wiki-maintenance.md](wiki-maintenance.md)에서 필요한 절차만 읽는다.

## 근거와 상태

중요한 주장에 필요한 범위만 아래 구분을 붙인다. 모든 문장에 형식적인 필드를 추가하지 않는다.

| 구분 | 의미와 근거 |
| --- | --- |
| 현재 구현·관찰 사실 | 이 프로젝트의 코드·자료·실제 실행에서 확인한 내용. 대상·버전·관찰 범위를 명시한다. |
| 확정 방향 | 이 프로젝트의 사용자 결정이나 이미 적용 중인 명시적 규칙. 결정 요지·날짜·적용 범위를 남긴다. |
| 제안 | 에이전트의 비교·추론·추천. 근거와 아직 필요한 검증·결정을 구분한다. |
| 보류 | 현재 범위에서 다루지 않기로 한 내용과 그 이유. |
| 미확인·재확인 필요 | 근거가 부족하거나 기존 근거가 달라진 내용. 부족한 확인을 구체적으로 적는다. |

주장을 옮기거나 요약할 때 이 구분과 적용 범위를 보존한다. 여러 문서에서 같은 출처를 인용해도 독립적인 근거가 여러 개 생긴 것은 아니다. 에이전트의 이전 요약·다른 위키·다른 모델의 동의만으로 미확인을 확정하지 않는다.

현재 동작과 의도는 서로 다른 질문이다. 코드가 결정을 아직 구현하지 않았다면 양쪽을 적는다. 코드 변경만으로 의도를 바꾸거나 새 외부 자료만으로 기존 결정을 폐기하지 않는다.

## 출처와 확인 범위

- 중요한 주장 가까이에 근거의 상대 링크 또는 원문 URL을 둔다. 링크의 어떤 함수·절·페이지가 근거인지 필요할 때 덧붙인다.
- 코드·참고 프로젝트는 대상 경로와 확인한 버전·커밋 등 이용 가능한 기준점을 남긴다. Git이 없으면 확인일과 실제 범위를 쓰며 가짜 기준점을 만들지 않는다.
- 외부 문서는 제목·원문 URL·필요한 적용 버전·확인일을 남긴다. 편집일·발행일·자료 확인일·테스트 실행일을 혼동하지 않는다.
- 저자·제목·연도·DOI·URL 등 필요한 출처 메타데이터가 제공되지 않았다면 ‘미제공’, 제공됐으나 검증되지 않았다면 ‘미확인’으로 표시한다. 필요한 값을 추측하거나 만들어내지 않는다. 해당하지 않거나 불필요한 값은 생략하고, 확인한 원문·발췌·파일 경로를 연결한다. 발췌를 확인한 범위를 원문 전체 검토로 표현하지 않는다.
- 대화에서 제공된 근거에 안정적인 URL·파일 경로가 없으면 출처를 ‘사용자 제공 입력(별도 링크 없음)’으로 표시하고, 근거 링크를 만들어내지 않는다.
- 부분 확인은 읽은 절·페이지·파일, 아직 보지 않은 범위와 결론의 한계를 적는다. 검색 결과·요약·추출된 본문만 읽었다면 원문 전체를 검토했다고 쓰지 않는다.
- 이미지·표·첨부·OCR 누락이 결론에 중요하면 별도로 확인한다. 확인할 수 없으면 그 부분을 미확인으로 유지한다.
- 위키에 필요한 짧은 요약과 근거 위치를 남긴다. 원문·대화·개인 데이터의 자동 수집이나 외부 문서 전체 복제를 기본으로 하지 않는다.

출처와 검토 범위는 해당 주제에 적는 것으로 시작한다. 여러 주제의 재사용이나 이어 읽기로 출처·검토 범위를 주제 문서 안에서 관리하기 어려워 별도 추적이 필요할 때 [자료 양식](../templates/source.md)으로 기록을 만들고 연결한다. 원자료의 사본과 파생 요약은 서로 구분한다.

## 문서와 연결

- 제목·첫 문단에 주제의 범위와 핵심 결론을 쓴다. 한 주장에 대한 기준 설명은 한 문서에 두고 다른 문서에서는 링크한다.
- 짧은 소문자·하이픈 파일명을 기본으로 하되 기존 프로젝트의 이름 규칙을 유지한다. 단순한 표기 통일을 위해 기존 파일을 이동하지 않는다.
- 일반 Markdown 상대 링크를 기본으로 한다. 실제로 존재하는 파일·절만 연결하고 예정 문서는 링크 대신 미확인 항목으로 쓴다.
- 관련 링크에는 관계나 함께 읽는 이유를 적는다. 링크 수·양방향 링크·페이지 수를 채우기 위해 의미 없는 연결을 만들지 않는다.
- 코드 설명·결정·자료 요약은 관련 주제 안에서 시작한다. 별도로 재사용할 필요가 있을 때 [주제](../templates/topic.md)·[결정](../templates/decision.md) 양식의 필요한 항목만 사용한다.
- 메타데이터는 문서 유지에 필요한 확인 기준과 상태부터 둔다. frontmatter·태그·고유 ID 체계는 기존 도구나 실제 탐색 문제가 요구할 때만 추가한다.

## 질문과 충돌

질문·충돌은 관련 주제에서 관리한다. 열린 항목에 쟁점·서로 다른 근거·다음 확인을 적고, 새 정보가 오면 기존 항목부터 해소하거나 남은 범위를 좁힌다. 같은 질문을 새 파일에 반복하지 않는다.

해결되면 본문의 현재 설명을 갱신하고 결정·검증 근거를 연결한다. 중요한 결정의 변경 이유는 이력에 남긴다. 여러 주제에 걸친 쟁점이 반복될 때만 별도 목록을 만들고 색인에서 연결한다.

## 색인과 이력

[index.md](index.md)는 현재 문서의 탐색 경로다. 새 문서에는 링크와 한 줄 설명을 추가하고 범위가 바뀌면 설명을 갱신한다. 커지면 주제별 하위 색인으로 나눌 수 있지만 루트에서 모든 문서에 도달할 수 있어야 하며 같은 전체 목록을 중복 유지하지 않는다.

[log.md](log.md)는 중요한 지식 변화의 시간순 기록이다. `## [YYYY-MM-DD] 유형 | 제목` 아래에 바뀐 지식·이유·영향받은 문서·실제 검증 또는 남은 한계를 짧게 적는다.

| 유형 | 기록할 일 |
| --- | --- |
| `ingest` | 자료·사용자 결정에서 새 지식을 통합했다. |
| `query` | 질문에서 얻은 재사용할 분석·합의를 반영했다. |
| `sync` | 코드·원자료의 변경과 위키의 설명을 맞췄다. |
| `lint` | 요청된 정합성 점검 결과나 의미 있는 수정·남은 문제를 기록했다. |
| `maintain` | 위키의 구조·운영 규칙을 바꿨다. |

이력은 한 작업의 중요한 변화 단위로 남긴다. 매 도구 호출·일반 질문·서식 수정·변경 없는 상시 확인마다 항목을 만들지 않는다. 기존 항목을 다시 쓰거나 삭제하지 않고 정정은 새 항목에서 이전 내용을 참조한다. 이력은 현재 상태와 1차 근거를 대신하지 않는다.
