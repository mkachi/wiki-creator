# LLM Wiki 프로젝트 템플릿

에이전트가 프로젝트의 근거·결정·구현 지식을 연결하고 다음 작업에서 다시 활용하도록 만드는 Markdown 지침이다. 소프트웨어 프로젝트를 기본 대상으로 하며, 프로젝트의 실제 도구·구조·권한을 따른다.

## 구성

| 파일 | 역할 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | 프로젝트 지침에 넣을 짧은 진입점과 반복 규칙. |
| [.agents/wiki/README.md](.agents/wiki/README.md) | 위키의 목적과 세 층의 관계. |
| [.agents/wiki/index.md](.agents/wiki/index.md) | 위키 문서를 찾는 단일 색인. |
| [.agents/wiki/project.md](.agents/wiki/project.md) | 프로젝트 목적·범위·기존 기준 링크·실제 경로·검증 방법을 채우는 시작 문서. |
| [.agents/wiki/wiki-schema.md](.agents/wiki/wiki-schema.md) | 근거·상태·문서·링크·이력의 공통 작성 기준. |
| [.agents/wiki/wiki-maintenance.md](.agents/wiki/wiki-maintenance.md) | 자료 반영·질문·동기화·점검 절차. |
| [.agents/wiki/log.md](.agents/wiki/log.md) | 중요한 지식 변경의 이력. 시작 시 실제 작업만 기록한다. |
| [.agents/templates/topic.md](.agents/templates/topic.md) | 주제 문서를 만들 때 필요한 항목만 고르는 양식. |
| [.agents/templates/source.md](.agents/templates/source.md) | 출처·검토 범위를 따로 추적할 필요가 있는 자료의 양식. |
| [.agents/templates/decision.md](.agents/templates/decision.md) | 이후 판단에 영향을 주는 결정의 양식. |

양식 폴더는 위키 내용 색인에 넣지 않는다. 양식의 `{{...}}`는 실제로 확인한 내용으로 바꾸며 자동 치환 도구를 전제하지 않는다. 해당하지 않는 항목은 생략하고, 모르는 값은 추측해 채우지 않는다.

## 새 프로젝트에 적용

1. 프로젝트의 기존 지침, 위키 색인과 그 문서가 가리키는 기준 자료, 사용자가 지정한 입력을 확인한다. 사용자가 전체 검토를 요청하면 대상 파일·절의 확인 범위와 미검토 범위를 구분해 남긴다. 파일이 있다는 사실이나 검색 결과만으로 내용을 검토했다고 보지 않는다. `AGENTS.md`가 없으면 이 템플릿의 파일을 시작점으로 사용하고, 있으면 필요한 규칙과 링크를 기존 구성에 통합한다.
2. 기존 위키가 있으면 그 경로와 내용을 우선하여 필요한 파일만 추가·통합한다. 정해진 위치가 없으면 프로젝트 문서 구조와 사용자 요청에 맞는 최소 경로를 선택하고, `.agents/wiki/`를 기본 시작 경로로 사용할 수 있다. 이는 필수 경로가 아니며 프로젝트 구조에 맞지 않으면 조정한다. 이 README는 적용 안내이므로 프로젝트의 루트 README를 대체하지 않는다.
3. `project.md`의 목적·범위·자료 경계·문서 언어를 사용자 요청과 허용된 프로젝트 자료에서 확인해 채운다. 명시적인 사용자 언어 요청을 우선하고, 별도 요청이 없으면 기존 위키·프로젝트 문서의 언어를 따른다. 기준이 없으면 현재 대화 언어를 사용한다. 새로 복사하는 템플릿 본문도 선택한 프로젝트 언어로 작성한다.
4. 실제 구조·실행 명령·검증 방법과 작업에 적용되는 기존 기준을 확인한다. 위키 운영, 저장소별 버전 관리, 언어·프레임워크별 코드 규칙, 도구별 빌드·테스트 규칙을 구분하고, 기준 문서의 위치와 적용 범위만 `project.md`에 연결한다. 샘플의 브랜치·자동 커밋 정책이나 특정 저장소 구조를 기본값으로 가져오지 않는다. 미확인은 그대로 표시하고, 중요한 방향·권한 판단이 걸린 부분만 사용자에게 질문한다.
5. 관련 주제 하나를 반영한 뒤 출처·상태·링크·색인·이력을 확인한다. 파일을 복사한 사실을 구현이나 동작 검증 완료로 기록하지 않는다.

기존 파일의 일괄 덮어쓰기·이동·삭제, Git 초기화·ignore 변경·자동 커밋·배포는 이 템플릿 적용에 포함되지 않는다. 사용자가 정한 기존 정책이 있으면 그 범위에서 별도로 수행한다.

## 프로젝트에 맞추는 항목

| 항목 | 기본값과 조정 기준 |
| --- | --- |
| 위키 경로 | 기존 경로 우선. 위치가 정해지지 않았다면 `.agents/wiki/`를 시작 경로로 쓸 수 있으나 필수는 아니다. 변경하면 진입 지침·색인·상대 링크도 함께 맞춘다. |
| 문서 언어 | 명시적인 사용자 요청, 기존 위키·프로젝트 문서, 현재 대화 언어 순으로 정한다. 코드 식별자·원문의 고유명은 보존한다. |
| 포함 범위 | 다음 작업에서 재사용할 프로젝트 지식·결정·제약·검증 근거. |
| 제외 범위 | 비밀정보·식별 가능한 개인정보·대화 원문·일회성 로그·관련 없는 자료. |
| 원자료 | 원래 코드·문서·공개 URL을 먼저 연결한다. 모든 자료의 로컬 사본을 만들지 않는다. |
| 버전 관리 | 기존 저장소 정책에서 브랜치·커밋 단위와 시점·메시지·병합·push/PR 경계를 확인한다. 위키의 추적·ignore·공유 여부를 임의로 정하거나, 명시되지 않은 자동 브랜치·커밋·병합을 추가하지 않는다. |
| 코드 규칙 | 프로젝트가 실제로 사용하는 언어·프레임워크와 기존 컨벤션의 적용 범위를 확인한다. 기술 프로필은 참고 후보이며 기존 규칙을 덮어쓰지 않는다. |
| 실행과 검증 | 프로젝트에서 확인한 명령을 사용한다. 특정 언어·패키지 관리자·빌드 경로를 전제하지 않는다. |

템플릿 채택·기본 경로 선택·자료 목록 등록은 ignore 대상의 열람 승인이 아니다. ignore된 자료는 기본적으로 제외하고, 사용자가 특정 파일을 지정해 비민감임을 확인했으며 상위 지침이 금지하지 않을 때만 필요한 범위에서 읽는다. 문제 해결에 필요한 예외도 상위 지침이 허용한 비민감 자료로 한정한다. 실제 환경 파일·인증 정보·개인정보는 읽지 않는다.

## 작게 시작하기

시작 문서는 운영에 필요한 최소 구성이다. 도메인 지식은 실제로 확인한 주제부터 추가한다. 추가 자료 폴더와 색인은 프로젝트의 기존 구조를 따르고 실제 필요가 있을 때만 만든다. 자료마다 요약 페이지를 만들거나 사람·개념마다 파일을 만들 필요는 없다.

양식으로 만든 문서는 위키 안의 관련 주제 위치에 두고 색인에서 연결한다. 자료 폴더의 색인을 만들면 위키의 관련 주제나 색인에서 연결하되 같은 목록을 복제하지 않는다.

일반 Markdown 상대 링크와 색인·텍스트 검색으로 시작한다. YAML frontmatter, wikilink, 그래프, 검색 서버, 고유 레코드 ID, 자동 수집은 기존 환경에 필요할 때 선택한다. 등록하지 않은 도구나 슬래시 명령이 작동한다고 가정하지 않는다.

## 다른 종류의 프로젝트

리서치·독서·기획에도 목적·근거·지식·운영 절차를 재사용할 수 있다. `project.md`의 구현·테스트 항목을 연구 대상·자료 버전·검증 방법으로 바꾸고, 코드가 없는 프로젝트에서는 sync의 코드 변경 대조만 생략한다. 원자료 변경은 ingest 또는 sync 절차에 따라 반영한다. 과학적 주장·외부 제품의 설명과 사용자의 채택 결정을 구분하는 원칙은 유지한다.

## 스킬과 함께 사용하기

이 묶음은 위키 작성·운영을 위한 시작 템플릿이며 단독 실행 도구나 에이전트 설치 파일이 아니다. 위키 생성 스킬은 관련 문서만 읽어 프로젝트의 경로·언어·정책에 맞게 적용한다.
